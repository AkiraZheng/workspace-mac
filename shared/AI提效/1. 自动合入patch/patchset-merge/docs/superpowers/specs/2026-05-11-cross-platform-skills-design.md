# Cross-Platform Skills Design

## Overview

将 merge-patchset、revert-patchset 两个 skill 从 Claude Code 独占改造为多平台支持，同时保持单一源文件维护。

## Platform Tiers

| Tier | Platforms | Strategy |
|------|-----------|----------|
| Native | Claude Code, OpenCode | 同一份 SKILL.md 直接服务，改动最小化 |
| Degraded | Gemini CLI, Copilot, Cursor, Generic | install.sh 裁剪生成自包含版本，内联 karpathy-guidelines |

## Key Research Findings

- OpenCode 原生支持 SKILL.md 格式（YAML frontmatter + Markdown）
- OpenCode 直接兼容 `~/.claude/skills/` 路径——当前 install.sh 部署的 skill 已能被 OpenCode 发现
- OpenCode 自动发现并加载 skill，不需要 superpowers 插件
- OpenCode 使用 `skill({ name: "xxx" })` 加载 skill，Claude Code 使用 `Skill("xxx")`
- OpenCode 权限通过 `opencode.json` 控制，不在 SKILL.md frontmatter 中声明
- 多余的 YAML frontmatter 字段（如 `allowed-tools`）OpenCode 自动忽略

## SKILL.md Changes

### 1. Frontmatter

Add `compatibility` field:

```yaml
---
name: merge-patchset
description: ...
compatibility: claude-code, opencode
allowed-tools: Bash(b4:*), ...
---
```

### 2. Preamble Section (前置技能加载)

Replace Claude-specific verification with platform-aware instructions:

```markdown
## 前置技能加载

**Claude Code**:
- verify superpowers plugin + karpathy-guidelines skill installed
- invoke: Skill("superpowers:using-superpowers") + Skill("karpathy-guidelines")

**OpenCode**:
- karpathy-guidelines auto-discovered, no manual verification needed
- ensure not denied in opencode.json permission.skill

**Other platforms (degraded)**:
- The degraded version generated by install.sh strips this entire preamble section
- karpathy-guidelines is inlined at the top of the output file, making it fully self-contained
- If you see this preamble text on a degraded platform, the wrong file was deployed — re-run install.sh
```

### 3. Core Content

No changes to: 核心约束, 工作流, 交互模式, 反模式.

## install.sh Changes

### New Flow

1. Detect environment: `which claude` / `which opencode` / `which gemini` → determine platforms
2. Deploy SKILL.md to appropriate paths per platform
3. Deploy karpathy-guidelines as independent skill (Native tier) or inline (Degraded tier)
4. Generate degraded versions for Tier 2 platforms
5. Check b4 tool (unchanged)

### Deployment Targets

| Platform | Skill Path | karpathy-guidelines |
|----------|-----------|---------------------|
| Claude Code | `~/.claude/skills/<name>/SKILL.md` | `~/.claude/skills/karpathy-guidelines/SKILL.md` |
| OpenCode | `~/.config/opencode/skills/<name>/SKILL.md` | `~/.config/opencode/skills/karpathy-guidelines/SKILL.md` |
| Gemini CLI | `~/.agents/skills/<name>/SKILL.md` | Inline into output |
| Copilot | `.github/copilot-instructions.md` (manual) | Inline into output |
| Cursor | `.cursorrules` (manual) | Inline into output |
| Generic | `dist/generic/<name>.md` | Inline into output |

### Degraded Version Generation

For platforms without skill systems, install.sh:
1. Reads SKILL.md
2. Strips the 前置技能加载 section
3. Prepends inlined karpathy-guidelines content
4. Writes to `dist/<platform>/<name>.md`

## Project Structure (Final)

```
patchset-merge/
├── SKILL.md                         # merge-patchset source
├── revert-patchset-SKILL.md         # revert-patchset source
├── karpathy-guidelines-SKILL.md     # behavioral guidelines source
├── install.sh                       # multi-platform installer
├── CLAUDE.md
├── README.md
└── dist/                            # generated Tier 2 outputs
    ├── copilot/
    ├── cursor/
    ├── gemini/
    └── generic/
```

## Sync Rule (Unchanged)

merge-patchset and revert-patchset share preamble, constraints, strategy tables, interaction patterns, and anti-patterns. Changes to shared sections in one must be synced to the other.
