## 阶段0：认识"页" —— 结构拆解法学 folio

**状态**：`[ ]` 未开始（小白教程第0/2课有部分底稿）

**思考题**

- 内核用什么描述一个物理页？它比书中的 `struct page` 多了什么？
- 内核怎么知道一个页有没有人用、被几个进程映射？
- 哪些字段是回收要用的？

**方法**：仿课程14，把 `struct folio` 按逻辑分组拆解，每个字段一句话职责，回收相关字段重点标注。

**比喻**

- `_refcount` = 数"现在有几个地方在用这个页"，归 0 才能释放
- `_mapcount` = 数"有几个 PTE 指着这个页"，-1 表示无人映射，回收前必须打回 -1

**代码位置**：`include/linux/mm_types.h:404`（struct folio）、`include/linux/page-flags.h:93`（PG_* 标志位）。

**产出**：一张 folio 结构拆解图，重点标出回收三件套：`lru`（排队用）、`flags` 里的 `PG_active`/`PG_referenced`（冷热标记）、`mapping`（找回映射用）。

## 阶段1：页与进程的关系 —— 手撕 RMAP

**状态**：`[ ]` 未开始（小白教程第4课有图3底稿）

**思考题**

- 回收一个页之前必须做什么？（断开所有映射）
- 内核怎么从一个物理页反向找到所有映射它的 PTE？
- 为什么 RMAP 是"以空间换时间"？

**方法**：仿课程15 手撕法，画指针关系图：

```
folio->mapping ──→ anon_vma ──(rb_tree)──→ anon_vma_chain ──→ vma ──→ PTE
```

**演进对比**（笨叔叔讲 2.6.11 → 4.0 的方法，这里换成 4.0 → 7.3）：

- 旧：`page->mapping` 直接指 anon_vma
- 新：`folio->mapping` 指向 `anon_vma`，`folio->_mapcount`/`_nr_pages_mapped` 计数辅助

**代码位置**：`mm/rmap.c` 的 `folio_referenced()`、`try_to_unmap()`（回收流程的地基，阶段3 直接调用）。

**产出**：一张 RMAP 指针关系图。

## 阶段2：页怎么排队 —— LRU 状态机 + 第二次机会法

**状态**：`[ ]` 未开始（小白教程第3课有图2底稿）

**思考题**

- 内核怎么区分冷页和热页？
- 5 条 LRU 链表分别放什么页？
- 为什么需要"第二次机会"？

**比喻**

- LRU 链表 = 图书馆的借阅排序，最近读过的放前面
- 第二次机会法 = 缓刑制度：第一次被抓（referenced）不处决，清标记放回，再犯才处理

**方法**：画两位饱和计数器状态机图（书中经典图，当前内核依然适用）：

```
inactive/unref ──访问──→ inactive/ref ──再访问──→ active/unref ──访问──→ active/ref
```

**代码位置**

- `mm/folio.c` 的 `mark_page_accessed()`：正向标记，谁在访问页时调用
- `mm/rmap.c` 的 `folio_referenced()`：反向检查，回收时清 access bit 统计引用
- `mm/vmscan.c:868` 的 `folio_check_references()`：法官判决，RECLAIM / KEEP / ACTIVATE

**具体例子**（仿课程16 例1）：用户进程第二次读同一文件页，跟踪 `mark_page_accessed()` 被调两次，观察页面从 inactive 升到 active。

**产出**：状态机图 + 判决逻辑表（`FOLIOREF_*` 三种走向的条件）。

## 阶段3：回收完整流程 —— 渐进式流程图法（★核心★）

**状态**：`[ ]` 未开始（小白教程第5课有图4底稿，但非渐进式）

**思考题**

- 谁触发回收？回收一个页要经过哪几步？
- 哪些页会被救回，哪些会被回收？

**方法**：完全仿课程16 第19-23页，同一张底图逐步叠加五条路径：

```
底图：  [活跃LRU] ←──→ [不活跃LRU] → 释放
```

- `①` 页面入LRU：`folio_add_lru_vma`（`mm/memory.c:5204`），匿名页/文件页各进哪条链
- `②` active→inactive：`shrink_active_list`（`vmscan.c:2065`），folio_referenced 检查引用，被引用的可执行页留下，其余降级 + set PG_workingset
- `③` inactive→active：`shrink_folio_list` 里的判决（`vmscan.c:1232`），folio_check_references 返回 ACTIVATE 的情况
- `④` 留在 inactive 再观察：返回 KEEP 的情况（被锁/正在回写/只访问一次的 page cache/脏页）
- `⑤` 真正回收：try_to_unmap → pageout/swap → 释放（新增：demote 到低层内存，书中没有）

每画一步，就去 `vmscan.c` 读对应代码验证（图码互补）。当前版本注意三点书中没有的：

- 所有 `page` 换成了 `folio`
- `shrink_folio_list` 入参带 `struct scan_control`，决策字段比书里多
- 新增 `demote_folios` 链表（内存分层）

**产出**：5 张渐进式流程图（博客核心配图）。

## 阶段4：谁来回收 —— 水位图 + 三个入口

**状态**：`[ ]` 未开始（小白教程第7课有图6/图7底稿）

**思考题**

- 内核什么时候开始回收？什么时候停？
- kswapd（异步）和直接回收（同步）为什么需要两套？

**比喻**

- 水位 = 水库的三个刻度线：低于 HIGH 不动、低于 LOW 清洁工（kswapd）上班、低于 MIN 所有人停下手里的活一起抢险（直接回收 + OOM 风险）

**方法**：仿课程16 第8页画全景图（当前版本把书中的 per-zone 改成 per-node）：

```
WMARK_HIGH ── kswapd 睡眠
WMARK_LOW  ── wakeup_kswapd (page_alloc.c:3435)
WMARK_MIN  ── __alloc_pages_slowpath → 直接回收 (page_alloc.c:4784)
```

三个入口的调用栈（自顶向下，注意汇聚点 `shrink_node()`，`vmscan.c:6239`）：

- 直接回收：`__alloc_pages_slowpath → try_to_free_pages → do_try_to_free_pages → shrink_zones → shrink_node`
- kswapd：`kswapd → balance_pgdat → kswapd_shrink_node → shrink_node`
- 主动回收：`madvise(MADV_PAGEOUT) / DAMON → reclaim_pages → shrink_folio_list`

**产出**：水位全景图 + 三入口调用栈（一个汇合点）。

## 阶段5：新旧对比 —— 演进对比图法

**状态**：`[ ]` 未开始（小白教程第9课有对照表底稿）

**思考题**

- 书里的代码为什么现在"对不上号"？哪些变了哪些没变？

**方法**：仿课程15 讲 2.6.11 → 4.0 的对比法，做左右并列对比：

| 旧（书/2.6） | 新（v7.3） | 为什么改 |
|---|---|---|
| `struct page` | `struct folio` | 大页时代 page 逐个处理太碎 |
| per-zone LRU | per-node + per-memcg lruvec | NUMA + cgroup 时代 |
| 两位计数器 LRU | + Multi-Gen LRU 分代 | 精确度高，扫描开销低 |
| 只能释放/swap | + demotion 内存分层 | 多层硬件（DRAM+PMEM+CXL） |
| 被动等水位 | + DAMON 主动监控 | 冷热检测与回收解耦 |

**产出**：一张对比总表（学完前面阶段后 30 分钟能填完，是博客"现代内核 vs 经典书籍"的卖点素材）。

## 终章：匿名页面的一生 —— 生命周期串联（检验学会没有）

**状态**：`[ ]` 未开始（小白教程第6课有 swap 底稿，但非完整生命周期叙事）

**方法**：用课程17 叙事法，不看资料完整讲一遍这个故事，讲不下去的地方就是没学会的地方：

```
do_anonymous_page 诞生（_mapcount=0, 进 inactive LRU）
  → 用户访问（PTE access bit 置位）
  → 回收扫描时 folio_referenced 发现引用（清 bit，记 referenced）
  → 降级/升级状态转换
  → 老化降到 inactive 尾部
  → shrink_folio_list 判决 RECLAIM
  → add_to_swap 分配 swap 槽位
  → try_to_unmap 断开所有映射
  → pageout 写入 swap 分区
  → __remove_mapping + 释放物理页
  → 进程再访问 → 缺页 → do_swap_page 换入，重新开始一轮
```

**产出**：匿名页面生命周期叙事（终章，串起全部）。

## 实验验证（笨叔叔课程4 的 QEMU 方法）

```bash

# 阶段4：观察水位
cat /proc/zoneinfo | grep -E "pages free|min|low|high"

# 施压制造回收（匿名页为主）
stress-ng --vm 4 --vm-bytes 80% --vm-hang 0 -t 60s
```
