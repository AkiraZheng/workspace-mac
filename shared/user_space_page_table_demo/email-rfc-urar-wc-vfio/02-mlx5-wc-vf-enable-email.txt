Subject: [PATCH 2/2] RDMA/mlx5: Add force_wc_vf module parameter for experimental VF WC support

This patch relaxes WC gating for mlx5 when running under VFIO,
allowing BF (BlueFlame) doorbells if WC mappings are available.

Currently, mlx5_ib_test_wc() disables WC support for VF devices:

  if (!dev->mdev->roce.roce_en &&
      port_type_cap == MLX5_CAP_PORT_TYPE_ETH) {
      if (mlx5_core_is_pf(dev->mdev))
          dev->wc_support = arch_can_pci_mmap_wc();
      return 0;  // <-- VF exits here without setting wc_support
  }

This causes bf_reg_size == 0 in userspace, leading to fallback to
non-BF doorbells and degraded latency (~0.5 usec overhead observed).

When VFIO is configured to allow WC mappings (via allow_wc_bar module
parameter), it is possible to enable BF safely in controlled environments.

This patch adds a module parameter to allow experimental WC support
for VFs when VFIO WC mapping is available:

  echo 1 > /sys/module/mlx5_ib/parameters/force_wc_vf

Note: This is experimental and should only be used in trusted single-tenant
environments where platform-specific testing has validated ordering requirements.
