# v3->v4 总结

需要的改进点
1. 将ioctl取消（接口相关的最后再修改）
    - 对于enable：在migration初始化的时候自动enable这个特性（KVM_SET_USER_MEMORY_REGION中）
    - 对于disable：在migration结束的时候自动disable这个特性（VM stops，但是目前还没找到在哪stop的）
    - 对于size：在enable的时候，根据当前 VM 的 memory usage 来自动选择大小。
2. HDBSSBR_EL2 的define中，把 GENMASK(55, 12 + sz) 删了，换成HDBSSBR_EL2_BADDR_MASK

3. enable的代码中，把size改成order，防止歧义。

4. 修改触发hdbss flush的位置，保证一些函数的干净性

5. 测试dirty ringDirty Ring脏页统计

6. 合入leo的 HACDBS patch(解决拆大页问题)

7. 将所有HDBSS相关的特性代码归档到arch/arm64/kvm/dirty_bit.c file (plus a header such as arch/arm64/include/asm/kvm_dirty_bit.h).

8. 迁移后,在迁入端页面发生权限变化时(W->RO时),需要把DBM标志去掉

9. 将添加DBM prot的操作放到每个可读页首次fault的时候就加上，这样可以在迁移的时候再减少一次trap，更干净。(argue,涉及的修改太多了,暂时先不考虑)

# todo #3 详细分析: 首次缺页自动加DBM

## 0. 目标

当前 DBM 只在热迁移日志阶段才添加 (mmu.c:1965):

```c
if ((*prot & W) && kvm->arch.enable_hdbss && memslot_is_logging(memslot))
    *prot |= KVM_PGTABLE_PROT_DBM;
```

这导致迁移启动时需要一次额外的写 trap: 首次缺页创建 W 页(无DBM) → 迁移WP→ guest 写→ trap→ relax_perms 加 DBM。

目标: 首次缺页创建 W+DBM，迁移时只需 WP 改权限(DBM 原位)，省一次 trap。

改造后的 DBM 条件:

```c
if ((*prot & KVM_PGTABLE_PROT_W) && kvm->arch.enable_hdbss && !s2vi->device)
    *prot |= KVM_PGTABLE_PROT_DBM;
```

移除了 memslot_is_logging 的时间守卫，加 !s2vi->device 显式排除设备页。

## 1. 前置依赖: ioctl → 迁移钩子 (Todo #2)

**问题**: 当前 enable_hdbss 在迁移 ioctl 时才设为 true。首次缺页发生在
VM 启动初期，此时 enable_hdbss==false，即使想加 DBM 也无从加起。

**方案**:
- 把 HDBSS 启停从 ioctl 路径迁移到 dirty logging 生命周期钩子
- enable 钩子: KVM_SET_USER_MEMORY_REGION(创建 memslot 时) → enable_hdbss
- disable 钩子: VM stops / migration ends → disable_hdbss
- 接口: 复用已实现的 kvm_arm_enable_hdbss_internal(kvm, order)
         和 kvm_arm_disable_hdbss_internal(kvm)

**涉及代码**: dirty_bit.c (enable/disable 函数已有), mmu.c (调用点从
ioctl 移到 memslot 创建路径), arm.c (去掉 ioctl 复杂逻辑，保留薄封装)

## 2. 坑1: 大页粒度 DBM + Lazy Split 导致脏页丢失

### 问题链路

首次缺页 → kvm_pgtable_stage2_map() 创建 2MB 大页 W+DBM
→ 迁移启动修改权限 W+DBM → RO+DBM
→ 大页不 trap(KVM 看不到写),硬件在大页粒度记录 dirty
→ HDBSS buffer 条目: 2MB 基地址 IPA
→ kvm_flush_hdbss_buffer() 只标记 1 个 4KB 页

### 已解决的保护

| 机制 | 位置 | 作用 |
|------|------|------|
| Eager split | mmu.c:1005-1006 | system_supports_hdbss() → split_page_chunk_size=PAGE_SIZE |
| DBM 提取 | pgtable.c:776-777 | kvm_pgtable_stage2_pte_prot() 从父PTE提取DBM |
| DBM 比较 | pgtable.c:788-789 | stage2_pte_needs_update() 检测DBM变化 |
| DBM 继承 | pgtable.c:1548 | stage2_split_walker() 子PTE继承父PTE的DBM |

### 拆页三条路径验证

| 路径 | chunk_size | 涉及函数 | 是否安全 |
|------|:---:|------|:---:|
| 全量拆 | PAGE_SIZE | kvm_mmu_split_memory_region() → kvm_mmu_split_huge_pages() | ✔ |
| 增量拆 | PAGE_SIZE | kvm_arch_mmu_enable_log_dirty_pt_masked() | ✔ |
| Lazy Split | **0** | kvm_mmu_split_huge_pages() 直接 return 0 | ✗ 不适用于HDBSS |

**结论**: HDBSS 场景下 patch 6 已保证 chunk_size != 0，Lazy Split 路径
不可达。但需确保 system_supports_hdbss() 早于 mmu init 执行。

## 3. 坑2: 非迁移场景修改权限时残留 DBM

### 问题

首次缺页加了 W+DBM，但 HDBSS 未启用(或已停用)时，如果其他路径修改页面
权限(W→RO)，DBM 位残留在 PTE 中:

```
RO+DBM = 硬件解释为"跟踪写"，guest 写入时硬件自动升级为 W+DBM(dirty)
       → 不 trap 到 KVM → KVM 无法拦截非法写 → 数据损坏
```

### 需要修改的代码路径

所有修改 S2 PTE 权限的路径，当目标 prot 不含 W 时必须清除 DBM:

```c
// 1. kvm_pgtable_stage2_relax_perms() (pgtable.c:1358+)
//    DBM 已处理 set |= DBM，需要对称加 clr:
if (!(prot & KVM_PGTABLE_PROT_W))
    clr |= KVM_PTE_LEAF_ATTR_HI_S2_DBM;

// 2. stage2_set_prot_attr() (pgtable.c:704+)
//    rebuild ALL bits from prot，需要:
if (!(prot & KVM_PGTABLE_PROT_W))
    attr &= ~KVM_PTE_LEAF_ATTR_HI_S2_DBM;

// 3. kvm_stage2_wp_range() → stage2_attr_walker()
//    需确认 walker 在设置 RO 时同步清除 DBM
```

**注意**: stage2_set_prot_attr 是重建全部属性，如果 prot 不含 DBM→attr
无 DBM，天然正确。但 kvm_pgtable_stage2_relax_perms 是 set/clr 增量修改，
需要显式处理 clr。

## 4. 坑3: 设备页不应加 DBM

### 问题

设备页(VM_PFNMAP/MIXEDMAP + !pfn_is_map_memory) 通过 s2vi->device 标识
(mmu.c:1932)。这些是 MMIO/PASSTHROUGH 地址，不应有 dirty tracking。

当前通过两个条件间接保护:
1. 设备页所在的 memslot 通常 dirty_bitmap==NULL → memslot_is_logging 为 false
2. mmu.c:1960: s2vi->device 短路给 W，但后续仍需 memslot_is_logging 过滤 DBM

但这是间接保护——如果设备所在槽恰好有 dirty_bitmap，当前代码也会给
设备页加 DBM。虽然实际场景中几乎不会发生(设备槽没有 dirty_bitmap)，
但改成首次缺页加 DBM 后条件变为:

```c
if ((*prot & W) && enable_hdbss && !s2vi->device)  // 显式排除
    *prot |= DBM;
```

**显式加 !s2vi->device 替代间接的 memslot_is_logging**。

### memslot_is_logging 当前过滤了什么

| 过滤对象 | 方式 | 可靠性 |
|----------|------|:---:|
| 非迁移普通页 | dirty_bitmap==NULL | 直接 |
| ROM/FW 只读槽 | KVM_MEM_READONLY | 直接 |
| 设备 MMIO 页 | dirty_bitmap 通常 NULL | 间接脆弱 |

去掉 memslot_is_logging 后:
- 非迁移页面加 DBM → 预期行为(todo 目标)
- ROM 页面不加 DBM → 不受影响(ROM 无法获得 W)
- 设备页需 **!s2vi->device** 显式排除

## 5. 坑4: 脏页计数标记不匹配

### 问题 (mmu.c:2069-2072)

kvm_s2_fault_map() 在映射成功后调用 mark_page_dirty_in_slot() 标记整个
mapping_size 范围的页面为脏。如果首次缺页加 DBM 导致页面可能已经被
硬件标记过 dirty，这里重复标记是否 safe?

**结论**: 不影响。mark_page_dirty_in_slot 是 set bitmap bit，幂等操作。
硬件 DBM dirty 通过 HDBSS buffer 异步消费，各自独立。
